## 1. Описание системы

**Daylink** — веб-приложение для управления личными задачами и дедлайнами. Позволяет добавлять задачи с описанием, категорией, приоритетом и сроком выполнения, отслеживать их статус и получать визуальную индикацию просроченных дедлайнов.

### Целевая аудитория

Приложение ориентировано на широкую аудиторию: студентов, фрилансеров, офисных работников — всех, кому нужно структурировать большое количество задач с разными сроками.

### Основной функционал

| Функция | Описание |
|---|---|
| Добавление задачи | Название, описание, дедлайн, категория, приоритет |
| Просмотр задач | Список с фильтрацией и сортировкой |
| Отметить выполненной | Toggle статуса задачи |
| Удаление задачи | Удаление по ID |
| Подсветка просроченных | Визуальная индикация через JS |
| Фильтрация | По статусу: все / активные / выполненные / просроченные |
| Сортировка | По дате создания / дедлайну / приоритету |

### Пользовательский сценарий

Пользователь открывает Daylink в браузере и видит список своих текущих дел. Чтобы добавить новую задачу, он вводит название, выбирает категорию (учёба / работа / личное), указывает приоритет и дату дедлайна, при желании добавляет описание — и нажимает «Добавить». Задача появляется в списке. По мере выполнения пользователь отмечает задачи выполненными. Просроченные дедлайны автоматически подсвечиваются красным.

## 2. Архитектура

### Технологический стек

**Backend:**
- Python 3.11
- FastAPI — веб-фреймворк
- SQLAlchemy — ORM для работы с базой данных
- Pydantic — валидация данных
- Uvicorn — ASGI сервер
- SQLite — база данных
- python-dotenv — переменные окружения

**Frontend:**
- HTML / CSS / JavaScript (vanilla)
- SPA подход: фронт общается с бэкендом через fetch-запросы, страница не перезагружается

**Инфраструктура:**
- Docker — контейнеризация
- GitHub Actions — CI/CD
- Semgrep — статический анализ безопасности (SAST)
- Trivy — анализ зависимостей (SCA/SBOM)

### Схема взаимодействия компонентов

```
Браузер (HTML/CSS/JS)
        │
        │ fetch запросы (JSON)
        ▼
FastAPI (src/main.py + src/routers/tasks.py)
        │
        │ Pydantic валидация
        │
        │ SQLAlchemy ORM
        ▼
SQLite (daylink.db)
```

### API эндпоинты

| Метод | Путь | Описание |
|---|---|---|
| GET | /tasks/ | Получить все задачи |
| POST | /tasks/ | Создать задачу |
| PATCH | /tasks/{id}/done | Toggle статуса выполнения |
| DELETE | /tasks/{id} | Удалить задачу |

### Модель данных

```python
class Task:
    id: int           # первичный ключ
    title: str        # название задачи
    description: str  # описание (опционально)
    deadline: datetime # дедлайн (опционально)
    category: str     # study / work / personal
    priority: str     # high / medium / low
    is_done: bool     # статус выполнения
    created_at: datetime # дата создания
```

## 3. Этапы разработки

### 1 — Репозиторий и README

Создан GitHub репозиторий, оформлен `README.md` с описанием проекта, функционала, стека, архитектуры и инструкции запуска. Настроен базовый Git-workflow с ветками и Pull Request.

### 2 — Базовая реализация

Реализован полноценный бэкенд на FastAPI с подключением SQLite через SQLAlchemy. Написан фронтенд на vanilla JS с тёмной темой, фильтрацией, сортировкой и визуальной индикацией просроченных задач. Приложение работает как SPA — без перезагрузки страницы.

### 3 — CI pipeline

Настроен GitHub Actions pipeline, который запускается при каждом Pull Request:
- `flake8` — проверка стиля и ошибок
- `black --check` — проверка форматирования
- `pytest` — запуск тестов

### 4 — Docker

Приложение упаковано в Docker контейнер на базе минимального образа `python:3.11-slim`. Добавлен `.dockerignore` для исключения лишних файлов. Образ весит ~150MB против ~900MB у базового `python:3.11`.

Запуск:
```bash
docker build -t daylink .
docker run -p 8000:8000 daylink
```

### 5 — Тестирование

Написаны два типа тестов:
- **Unit тесты** — проверка схем и валидации данных
- **Functional тесты** — проверка API эндпоинтов через тестовый клиент FastAPI с изолированной тестовой базой данных

Тесты интегрированы в CI и запускаются автоматически при каждом PR.

### 6 — SAST (Semgrep)

Подключён Semgrep для статического анализа безопасности. При первом запуске обнаружена уязвимость:

> `html.security.audit.missing-integrity` — отсутствие атрибута `integrity` на CDN ссылке в `index.html`

**Проблема:** без атрибута `integrity` браузер не проверяет хэш загружаемого файла, что открывает возможность для XSS атаки при компрометации CDN.

**Решение:** добавлен атрибут `integrity` с SHA384 хэшем файла и `crossorigin="anonymous"`.

После исправления Semgrep показывает 0 findings.

### 7 — SCA/SBOM (Trivy)

Проведён анализ зависимостей через Trivy. Сгенерирован SBOM в формате CycloneDX (`sbom.json`).

**Результаты первичного анализа:** 32 уязвимости (12 HIGH, 16 MEDIUM, 4 LOW).

**Анализ:** большинство уязвимостей оказались в системных пакетах Ubuntu (`cryptography`, `pillow`, `wheel`), которые попали в `requirements.txt` через `pip freeze`. Это не прямые зависимости проекта.

**Решение:**
1. Очищен `requirements.txt` — оставлены только прямые зависимости проекта
2. Обновлены уязвимые пакеты: `black 24.10.0 → 26.3.1`, `pytest 8.3.3 → 9.0.3`, `python-dotenv 1.0.1 → 1.2.2`

**Итог:** 0 уязвимостей в прямых зависимостях проекта.

## 4. Тестирование

### Покрытие

| Тест | Тип | Что проверяет |
|---|---|---|
| `test_task_create_defaults` | Unit | Дефолтные значения схемы TaskCreate |
| `test_task_create_with_all_fields` | Unit | Создание задачи со всеми полями |
| `test_task_title_cannot_be_empty` | Unit | Валидация обязательного поля |
| `test_get_tasks_empty` | Functional | GET /tasks/ на пустой базе |
| `test_create_task` | Functional | POST /tasks/ создаёт задачу |
| `test_create_and_get_task` | Functional | Задача появляется в списке |
| `test_mark_task_done` | Functional | PATCH /tasks/{id}/done меняет статус |
| `test_delete_task` | Functional | DELETE /tasks/{id} удаляет задачу |
| `test_delete_nonexistent_task` | Functional | 404 при удалении несуществующей задачи |
| `test_mark_nonexistent_task_done` | Functional | 404 при toggle несуществующей задачи |

### Изоляция тестов

Тесты используют отдельную базу данных `test.db`, которая создаётся перед каждым тестом и удаляется после — это гарантирует независимость тестов друг от друга.

### Запуск тестов

```bash
pytest tests/ -v
```

## 5. Безопасность

### SAST — Semgrep

Semgrep запускается в CI при каждом PR и проверяет код на потенциальные уязвимости. Используется конфигурация `--config=auto` — автоматический выбор правил на основе языков проекта (456 правил).

Найденная уязвимость исправлена (см. ДЗ 6).

### SCA — Trivy

Trivy анализирует `requirements.txt` на наличие CVE в зависимостях. В CI настроена проверка только HIGH и CRITICAL уязвимостей чтобы не блокировать PR из-за низкоприоритетных проблем.

Сгенерирован SBOM в формате CycloneDX — стандартный формат для передачи информации о составе программного обеспечения.

### Переменные окружения

Чувствительные данные (строка подключения к БД) хранятся в `.env` файле, который добавлен в `.gitignore` и никогда не попадает в репозиторий.

### CI/CD pipeline (полная конфигурация)

```yaml
name: CI
on:
  pull_request:
    branches:
      - main
jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-python@v4
        with:
          python-version: "3.11"
      - run: pip install uv
      - run: uv pip install --system -r requirements.txt
      - run: uv pip install --system flake8 black pytest httpx semgrep
      - run: flake8 src --max-line-length=100
      - run: black --check src
      - run: pytest tests/ -v
      - run: semgrep scan --config=auto src/ --error
      - run: trivy fs --scanners vuln --severity HIGH,CRITICAL requirements.txt
```
